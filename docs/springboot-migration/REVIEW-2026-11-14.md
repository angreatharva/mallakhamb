# Review of the migration plan, skills and code-gen kit (2026-11-14)

A full read-through of revisions 1–3, looking for mistakes, contradictions and
gaps. Every finding below has been **fixed in place** in the documents it
names. The build tool also changed from Maven to **Gradle** (owner decision,
2026-11-14), listed last.

Severity: **High** = would have broken the build, produced wrong results or
blocked a stage. **Medium** = would have cost real rework or tokens.
**Low** = wording or consistency.

| F11 | High | 09 §2.1 | The rulebook carried COP section `ref`s, but the first edition is generated from Node, which has no section references (except checklist text). ## Gradle (owner decision, 2026-11-14)

| # | Change | Where |
|---|---|---|
| G1 | Gradle 9 (Groovy DSL), wrapper with pinned `distributionSha256Sum`. Spring Boot Gradle plugin, Java toolchain 25 | 02 §3, §5; 05; ADR-010; README |
| G2 | **Gradle subprojects enforce purity at compile time:** `:kernel` (JDK only), `:engines` (kernel only; includes the rulebook), `:app` (Spring Boot; all modules as packages). An engine can't import Spring or Mongo because they aren't on its classpath. ArchUnit still guards the module boundaries inside `:app` | 02 §3, 04 §6 |
| G3 | One **version catalog** (`gradle/libs.versions.toml`), the single source for every dependency version; dependency locking and `verification-metadata.xml` (checksums) | 02 §5, 05 §3, 08 |
| G4 | Convention plugin in `build-logic/` (toolchain, Error Prone + NullAway via `net.ltgt.errorprone`, Spotless with palantir-java-format, test setup), so every subproject builds the same way | 02 §3, 07 §3 |
| G5 | Reproducible jars (`preserveFileTimestamps = false`, `reproducibleFileOrder = true`) and the build cache shared across worktrees | 05 §3, 07 §5 |
| G6 | Commands: `./gradlew build`, `./gradlew :app:bootJar`, `./gradlew portCheck --op=<id>`, `./gradlew :tools:copCheck` (`gradlew.bat` on Windows) | 05, 06, 07, skills |
