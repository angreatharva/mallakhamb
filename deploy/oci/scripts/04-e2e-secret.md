# Stage 4 — the throw-away database for the nightly e2e check (owner does this; ~10 min)

The nightly lifecycle check (deploy/oci/PLAN.md O14) seeds a whole season into its **own** database,
`<db>_e2e`, through a second, internal copy of the API, then drops it. It must not be able to touch the
real database, so it gets an Atlas user that can only reach `<db>_e2e`. Secrets never go through chat
or git: the password goes into Atlas and the Vault, nowhere else.

Staging today: real database `BRMC_dev` → e2e database **`BRMC_dev_e2e`**.

1. **Atlas → Database Access → Add New Database User**
   - Authentication: Password. Username **`mallakhamb_e2e`**. Autogenerate a password, copy it.
   - Database User Privileges → **Specific Privileges** → add **both**:
     - `readWrite` @ `BRMC_dev_e2e`
     - `dbAdmin` @ `BRMC_dev_e2e` (`readWrite` alone can't drop the database, and the run drops it twice)
   - Nothing on `BRMC_dev`, nothing "any database". → **Add User**.
2. **Atlas → Network Access:** both server IPs are already there (`137.23.63.84`, `130.210.4.142`).
   The check runs on the standby too, so both are needed. Never `0.0.0.0/0`.
3. **The connection string:** take the app's string (Atlas → Connect → Drivers, the same cluster
   host as the app), and change two things: user `mallakhamb_e2e` with its password, and the
   database path **`/BRMC_dev_e2e`**:

   ```
   MONGODB_URI='mongodb+srv://mallakhamb_e2e:<password>@<cluster host>/BRMC_dev_e2e?retryWrites=true&w=majority'
   ```

   One line, single quotes, nothing else in the file. If the password has `@ : / ? # [ ] %`,
   percent-encode it (Atlas's autogenerated passwords are letters and digits).
4. **OCI → Cloud Shell:**

   ```bash
   nano ~/e2e.env          # paste the one line, Ctrl+O Enter, Ctrl+X
   C=$(oci iam compartment list --compartment-id $OCI_TENANCY --name mallakhamb-prod --query 'data[0].id' --raw-output)
   VID=$(oci kms management vault list -c $C --all --query "data[?\"display-name\"=='mallakhamb-prod-bom-kv-01' && \"lifecycle-state\"=='ACTIVE'].id | [0]" --raw-output)
   MGMT=$(oci kms management vault get --vault-id $VID --query 'data."management-endpoint"' --raw-output)
   KID=$(oci kms management key list -c $C --endpoint $MGMT --all --query "data[?\"display-name\"=='mallakhamb-prod-bom-key-01'].id | [0]" --raw-output)
   grep -qxE "MONGODB_URI='mongodb(\+srv)?://mallakhamb_e2e:[^']+/[A-Za-z0-9_]+_e2e(\?[^']*)?'" ~/e2e.env && \
   oci vault secret create-base64 -c $C --vault-id $VID --key-id $KID \
     --secret-name mallakhamb-prod-bom-secret-e2e-env \
     --secret-content-content "$(base64 -w0 ~/e2e.env)" \
     --wait-for-state ACTIVE --query 'data.id' --raw-output \
   || echo "FIX: the file must be exactly one MONGODB_URI='...' line, user mallakhamb_e2e, database ending in _e2e"
   shred -u ~/e2e.env
   ```

5. Send Claude the printed `ocid1.vaultsecret...` (an ID, not a secret). Claude runs
   `install-e2e.sh <ocid>` on both servers, a first run by hand on the standby, then on the active,
   and only then switches the timers on.

The VMs' policy (`mallakhamb-prod-pol-app`) already allows `read secret-bundles` in the compartment,
so no IAM change is needed.
